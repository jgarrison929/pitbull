# 5.1.1: dependencies, float, and the critical path

Status: spec, revised 2026-10-25 at 11:05 AM (PT) against `main` at `9114836a`. Target release **2026-11-03**. Depends on 5.1.0 for persisted activities and links UI. PRD: [5.1 Schedule](../prd/5.1-schedule.md).

**In flight (2026-10-25).** Builders are landing the CPM engine as a pure library in `v5/src/lib/cpm.ts` (`runCpm`): CI checks 1 to 6 plus the 1,000-activity performance check. That slice has **no database writes and no UI**. Wire-up to `schedule.ts`, link actions, seed links, and Gantt critical-path highlight follow once 5.1.0 is on `main`.

5.1.1 replaces the hand-typed early dates from 5.1.0 with a CPM pass. The PM draws finish-to-start and start-to-start links with whole-day lag. The engine fills early and late dates, total float, and the critical path. A save that makes a cycle is refused.

## Why this is second

Without logic, the Gantt chart is a bar list. The [schedule intel](../intel/schedule.md) scopes CPM-lite as finish-to-start and start-to-start with whole-day lag, one calendar, forward and backward pass, total float, and the critical path (recommendation 4). Float and the critical path are what a PM demos after "show me the schedule".

## User stories

1. As the PM, I link B finish-to-start after A, and B's early start moves to the next working day after A's early finish.
2. As the PM, I see total float on each activity and a critical-path highlight on the Gantt chart.
3. As the PM, when I draw a link that makes a cycle, the save is refused and the schedule is unchanged.
4. As the PM, I add a start-to-start link with a two-day lag and the successor starts on the correct working day.
5. As the executive, I see the job finish date on the portfolio equal the critical path's early finish.

## Rules

- Link types in 5.1.1: `finish_to_start` and `start_to_start` only. Finish-to-finish and start-to-finish are refused with a reason that names the supported types (recommendation 4).
- Lag is a whole number of working days on the successor's calendar. Negative lag is refused.
- Only the PM creates, edits, and deletes links.
- After every accepted write to an activity, a link, a holiday, or a duration, the server runs the CPM pass for that job inside the same transaction. Readers never see a half-updated graph.
- Early dates come from the forward pass. Late dates and total float come from the backward pass. An activity is critical when total float is 0 (InEight's default threshold is 0 hours, C17).
- An activity with no predecessor starts on the job's data date (the seed's job start, or the latest "start no earlier than" constraint on that activity). This matches Scheduling mode in InEight (C18) without Planning mode's free-floating packages.
- A cycle is refused on save. The refusal names the cycle (for example A → C → D → A). Nothing is written (acceptance check 5).
- Cost item current dates still follow linked activities' early dates through `syncCostItemDatesFromActivities` (5.1.0). PV still reads those columns until 5.1.2.
- Stale `version` checks from 5.1.0 still apply to activity edits. Link writes bump every activity that the CPM pass changes.

### Engine sketch

```ts
// v5/src/lib/cpm.ts (sketch)
export type LinkType = "finish_to_start" | "start_to_start";

export type CpmActivity = {
	id: string;
	durationDays: number;
	startNoEarlierOn: string | null;
	earlyStartOn: string;
	earlyFinishOn: string;
	lateStartOn: string;
	lateFinishOn: string;
	totalFloatDays: number;
	isCritical: boolean;
};

export type CpmLink = {
	predecessorId: string;
	successorId: string;
	type: LinkType;
	lagDays: number;
};

/**
 * Pure function. calendar supplies nextWorkingDay / prevWorkingDay / addWorkingDays.
 * Throws CycleError with the cycle path when a cycle exists.
 * Durations and lag count working days. Early finish is inclusive.
 */
export declare function runCpm(
	activities: readonly CpmActivity[],
	links: readonly CpmLink[],
	jobStartOn: string,
	calendar: WorkingCalendar,
): CpmActivity[];
```

One pure function owns the math. The server module loads rows, calls `runCpm`, and writes the results. Unit tests call `runCpm` with the intel fixture and never touch the database.

## Out of scope

- Baselines and switching PV onto baseline dates (5.1.2).
- File import (5.1.3).
- Finish-to-finish, start-to-finish, negative lag, multiple calendars, constraints other than "start no earlier than", sub-critical float paths, and resource leveling.
- Progress override and retained-logic modes for out-of-sequence progress (C16). 5.1.1 always uses retained logic: a successor cannot start before its predecessor's logic allows, even if the predecessor shows field progress.

## Trust-bar risks

- **Wrong float (item 3).** A one-day off-by-one in working-day math mislabels the critical path and teaches the wrong SPI story in 5.1.2. Checks 1 to 6 pin the intel fixture in CI.
- **Half-updated graph (item 6).** The CPM pass runs in the same transaction as the write. A failed pass rolls back the write.
- **Cycle message (item 1).** The refusal must name the cycle. A generic "invalid link" fails the check and fails a demo.
- **Performance (item 1).** The seeded graphs stay under 100 activities. A unit test runs `runCpm` on 1,000 activities in under 50 ms on the CI runner so a future seed stress job does not surprise us.
