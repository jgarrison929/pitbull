## User stories

1. As the PM, I add activities on 25-031 with a code, a name, and a duration in working days, and I see them on a Gantt chart.
2. As the PM, I link cost item 04-210 to activity C, and the cost item's planned dates become C's early start and early finish.
3. As the PM, I set Thanksgiving as a holiday on the job calendar, and an activity that spans it takes one more calendar day.
4. As the superintendent, I add a plan line by picking an activity, and the line shows that activity's name and cost items.
5. As the foreman on a phone, I see the activity name on today's plan line.
6. As the executive, I open a job and see the Gantt chart read-only.

## 5.1.0-a: schema, calendar, activities, seed

**Migration: 0020** (`0020_schedule_activities.sql`).

**Files.** `v5/src/db/schema.ts` tables `job_calendars`, `calendar_holidays`, `activities`, `activity_cost_items` (PRD data model sketch). Seed Cedar graph + holidays + short graphs on 24-118 and 24-077. No UI. No assistant actions.

### Rules

- An activity belongs to one job. Its code is unique on that job.
- Duration is a whole number of working days, at least 1 and at most 3,650.
- The job has one calendar. Default work days are Monday to Friday. Holidays are dates with no work.
- Early start and early finish in 5.1.0 are entered by the PM (or set by the seed). 5.1.1 replaces them with the CPM pass. Until then, early dates equal the dates the PM typed, late dates equal early dates, total float is 0, and `is_critical` is false for every activity.
- A leaf cost item may link to zero or more activities. A summary WBS code is refused at write time in 5.1.0-b.
- A draft-estimate job (26-010) has no schedule rows in the seed.

### Seed and demo data

## 5.1.0-b: schedule server module and typed actions

**Files.** New `v5/src/server/schedule.ts` owning `syncCostItemDatesFromActivities` and all schedule writes. `schedule.*` keys in `assistant/actions.ts` and `route.ts`. Depends on 5.1.0-a types.

### Rules

- Only the PM creates, edits, and deletes activities and calendar holidays. Other roles are refused with refusal wording on the rail.
- When a cost item has one or more linked activities, its `planned_start_on` becomes the earliest early start and its `planned_finish_on` becomes the latest early finish of those activities. The write goes through `syncCostItemDatesFromActivities`. No other module writes those columns for a linked item.
- When a cost item has no linked activities, its planned dates stay as the seed or the PM left them.
- A draft-estimate job refuses every schedule action with "Approve the estimate before scheduling".
- A save with a stale `version` is refused and names the other editor (schedule intel I8).

### Typed actions

All actions go through `run()` with `writes: true`.

| Action | Arguments | Role |
|---|---|---|
| `schedule.addActivity` | `job`, `code`, `name`, `durationDays`, `startOn` | pm |
| `schedule.editActivity` | `job`, activity (code or id), fields, `version` | pm |
| `schedule.removeActivity` | `job`, activity, `version` | pm |
| `schedule.linkCostItem` | `job`, activity, `costCode` | pm |
| `schedule.unlinkCostItem` | `job`, activity, `costCode` | pm |
| `schedule.setHoliday` | `job`, `date`, `name` | pm |
| `schedule.removeHoliday` | `job`, `date` | pm |

### Acceptance checks (staging)

1. **Cost item dates follow the link.** Role: PM. On `/app/jobs/25-031`, after linking 04-210 to C (seed may already link it), planned start and finish equal C's early start and early finish. Unlink and link again keeps the same rule.
2. **Many activities to one cost item.** Link 04-210 to B and C. Expected: planned start is the earlier of B and C starts, planned finish the later of B and C finishes (schedule intel, acceptance check 6).
3. **Holiday lengthens an activity.** Set a holiday on a working day inside C's span. Expected: C's early finish moves one working day later, and 04-210's planned finish moves with it when linked. Remove the holiday and C returns.
4. **Draft job refused.** `schedule.addActivity` as the PM on 26-010 is refused with "Approve the estimate before scheduling".
5. **Role refusal.** As the superintendent, try "Add activity X on 25-031". Expected: refused, rail chip "Couldn't add activity on 25-031".
6. **Stale version.** Open C in two sessions. Edit the name in session 1 and save. Edit the duration in session 2 and save. Expected: session 2 is refused and names Marcus Lee (or the session 1 user).

### Out of scope

- Gantt rendering. Plan-line picker. CPM (5.1.1).

## 5.1.0-d: plan-line activity link

**Migration: 0021** (`0021_plan_line_activity_id.sql`).

**Files.** `daily_plan_lines.activity_id` nullable FK, `dailyPlan.addLine` / `updateLine` accept activity code, superintendent plan-card activity picker, seed Bridge Crew 2 lines linked to C and E.

### Rules

- When `activity_id` is set, writes copy the activity name into the existing `activity` text column so older reads keep working.
- The cost item on the line must be linked to that activity, or the action is refused.
- The picker lists activities whose dates cover the plan date.
- A line with no activity id keeps free-text behavior for plans that predate 5.1.0.

### Acceptance checks (staging)

1. **Plan line links to an activity.** As the superintendent, create today's plan on 25-031 for Bridge Crew 2 (5.0.1 flow) and add a line by picking activity C. Expected: the line's activity name is "Pier columns", its cost item is 04-210, and the foreman at 390 px sees that name.
2. **Wrong cost item refused.** On a line linked to C, try to set the cost item to 07-410 (not linked to C). Expected: refused.
3. **S-curve still reads current dates.** On `/app/jobs/25-031`, if 5.0.3 Part A is deployed, the S-curve's last planned-value point still equals the Current Budget tile to the cent. PV has not moved to a baseline yet.

- **Visual baselines (item 5).** The job page gains a Schedule section. Add a desktop and phone baseline at 0-pixel tolerance.
- **Relative seed dates (item 2).** Staging dates move with `seedNow()`. Checks that need the intel's November 2026 ladder run in CI under a frozen seed clock.
