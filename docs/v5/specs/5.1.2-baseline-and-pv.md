## Why this increment

SPI is only meaningful if planned value reads frozen dates (I4). If PV tracks current activity dates, every slip moves PV with the work and SPI drifts toward 1.00. InEight keeps baselines as locked schedules (C6, C7). Pitbull keeps one current schedule and a list of immutable baselines (PRD shape 2).

Locked wording: planned value is "PV dates from the baseline schedule, linear spread" (I3). The linear spread stays the M4 function. Only the date pair changes. A CPM finish is inclusive, so the call into `plannedValueCents` passes **finish + 1 calendar day** as `finishExclusive` (schedule intel acceptance check 7; 5.1.1 CI check 6).

## User stories

1. As the PM, I set a baseline named "Award baseline" on 25-031, and the S-curve's planned line stops moving when I slip an activity.
2. As the PM, when I try to edit a baseline date, the product refuses.
3. As the PM, I re-baseline with a reason, and the old baseline stays readable while PV switches to the new one.
4. As the executive, I see SPI change when the first baseline lands, and the release notes show before and after.

## Rules

- Only the PM sets or re-baselines. Other roles are refused.
- Setting the first baseline copies each activity's current early start, early finish, and duration into `baseline_activities` for a new `schedule_baselines` row.
- After any baseline exists for the job, `pvDatesForCostItem` returns the min baseline start and max baseline finish among linked activities for the **latest** baseline, with `finishExclusiveOn = finishOn + 1 calendar day`. Current activity dates drive the Gantt and forecast finish only.
- Before the first baseline, PV keeps reading `cost_items.planned_start_on` / `planned_finish_on` (5.1.0 sync).
- Baseline rows are immutable. Edits to baseline dates through the screen or the assistant are refused.
- Re-baseline requires a non-empty reason, writes a new baseline row, and leaves prior baselines readable (I4, acceptance check 9).
- Seed sets one baseline on 25-031 named **Award baseline** after the graph (and 5.1.1 links when present) is built.

## Out of scope

- Multiple simultaneous "active" baselines for PV (latest wins).
- Snapshot slots beyond the append-only list (InEight C14).
- Non-linear PV curves.
- Import of baseline tables from XER (5.1.3 may import activities; baseline set stays a Pitbull action unless the import slice explicitly adds it).

## Trust-bar risks

- **Visible proof (item 3).** Release notes and verify evidence list before and after SPI for each active job.
- **Wrong finishExclusive (item 6).** Off-by-one makes SPI and the S-curve lie. Pin check 2 in CI.
- **Empty baseline list (item 1).** Before the first baseline, show guidance to set one. Do not show an empty baseline bar.
