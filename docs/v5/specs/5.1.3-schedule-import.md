## Why this increment

Native activity-to-cost-item links are the product edge (I1). Import is how a contractor who already lives in P6 or Microsoft Project gets a graph into Pitbull without retyping. Intel puts import after the native model (recommendation 7). XER and Microsoft Project XML cover both tools without a binary `.MPP` parser (I6). Binary `.MPP` stays out.

InEight Control's XER path matches on a typed Schedule ID (C34–C36). Pitbull import creates or updates activities in the same database the cost items already use. Cost-item links are **not** inferred from Schedule IDs in 5.1.3. The PM links cost items after import (or keeps 5.1.0 seed links on demo jobs). Report anything that did not transfer by type and count (recommendation 7).

## User stories

1. As the PM, I import a valid XER into 25-031 and see activities, calendars, and FS/SS links with lag.
2. As the PM, when one relationship points at a missing activity ID, the import writes nothing and names the gap.
3. As the PM, I import a Microsoft Project XML file the same way.
4. As the PM, the import summary lists skipped constructs (for example constraints) with counts, not silent drops.

## Rules

- Only the PM imports. Draft-estimate jobs refuse import.
- Import is **all-or-nothing**: any row error rolls back the whole file (same honesty as M2 estimate CSV).
- Supported in 5.1.3: activities (code, name, duration), job calendar + holidays when present, finish-to-start and start-to-start links with whole-day lag when 5.1.1 tables exist.
- Unsupported constructs are counted and listed in the summary. They do not fail the import by themselves unless they leave the graph unloadable (for example a link to a missing id fails the import).
- Codes must be unique on the job after import. Conflict with an existing code on a replace-import is refused unless the PM confirms replace in the typed action (`mode: "replace" | "merge"`). **Default for 5.1.3 verify:** `replace` on a job that has only seed activities in the sandbox check, or import onto a job cleared of activities in the check setup.
- Do not invent cost-item links from XER activity IDs (refuse the InEight Schedule ID typing path, C34).
- After a successful import, run the 5.1.1 CPM pass when links exist. Do not auto-set a baseline; the PM sets one (5.1.2).
- File size limit: refuse above 10 MB with a clear reason.

### Parser sketch

```ts
// v5/src/lib/schedule-import/xer.ts (sketch)
export type ScheduleImportDraft = {
	activities: { code: string; name: string; durationDays: number; startOn?: string }[];
	links: {
		predecessorCode: string;
		successorCode: string;
		type: "finish_to_start" | "start_to_start";
		lagDays: number;
	}[];
	holidays: { on: string; name: string }[];
	skipped: { kind: string; count: number; sample?: string }[];
};
export declare function parseXer(bytes: Uint8Array): ScheduleImportDraft | { error: string };
export declare function parseMspXml(bytes: Uint8Array): ScheduleImportDraft | { error: string };
```

One apply function in `schedule.ts` writes the draft inside a transaction.

## Acceptance checks

1. **XER happy path (staging or CI against staging upload).** Role: PM. Import `cedar-ok.xer` into a clean approved job (or 25-031 after removing seed activities in the check). Expected: 40 activities only if the fixture has 40; for the Cedar fixture, activities A–D (and E if present) match codes and durations. Links match 5.1.1 topology when present. Summary `skipped` may be non-empty but lists kinds and counts.
2. **XER all-or-nothing.** Import `cedar-missing-pred.xer` (one relationship to a missing activity ID). Expected: nothing written. Error names the activity and the missing ID (schedule intel check 11).
3. **Microsoft Project XML happy path.** Import `cedar-ok.xml`. Expected: same graph rules as check 1.
4. **Role refusal.** As superintendent, import refused: "Couldn't import schedule on 25-031".
5. **Draft refused.** Import on 26-010 refused with estimate wording.
6. **No Schedule ID coupling.** After import, cost items are not auto-linked. 04-210 links remain only if the PM (or seed) linked them.
7. **Crawl.** Import control is PM-only on the Schedule page. Other roles see read-only schedule. Under 1.5 s, 0 banned strings.

CI-only:

8. Parser unit tests cover skipped constraint rows counted in `skipped` without failing the draft.
9. File over 10 MB refused before parse.

## Out of scope

- Binary `.MPP` (I6).
- Resource assignments, resource leveling, curves (C44, C45 leave-outs for 5.1).
- Program / multi-project master XER as multiple Pitbull jobs (C42).
- Round-trip export to XER.
- Auto baseline on import.
- Mapping XER activity IDs to cost items by Schedule ID (C34).

## Trust-bar risks

- **Silent drop (item 3).** Skipped types must appear in the summary with counts.
- **Partial write (item 6).** One transaction. Failed apply leaves the prior schedule unchanged.
- **Unknown XER tables (U1).** Document skipped kinds as we learn them; expand fixtures rather than guessing.
